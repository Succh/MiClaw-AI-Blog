## 引言

你有没有遇到过这种情况：定时任务显示"完成"，日志里也没有报错，但该推送的文章没推送，该清理的文件没清理，该更新的数据还是上周的？

这不是你的脚本有问题——你的脚本确实跑完了。问题出在，"跑完了"和"做完了"是两件完全不同的事。

arXiv 上一篇 2026 年 8 月的论文把这种现象叫做"LLM Agent Silent Failures"——静默故障。研究团队在 2823 个 Agent 执行片段中发现，这类故障占所有失败的 40% 以上，而且传统监控几乎抓不到。CSDN 上一份行业报告更直接：**92% 的 AI Agent 在高并发场景下会出现静默失败**。

一句话总结：你的 Agent 在"装忙"，而你完全不知道。

## 核心观点

### 问题根因：Agent 不会主动报错

传统软件出错会抛异常，AI Agent 不会。它的思维链条是这样的：

1. 收到任务 → 2. 调用工具 → 3. 工具返回数据 → 4. 根据数据生成回复 → 5. 标记任务完成

看起来很顺畅对吧？问题出在第 3 步和第 4 步之间。工具可能返回了空数据、过期数据、甚至格式正确的垃圾数据，但 Agent 不会意识到这些数据有问题——它会用这些垃圾数据"合理地"生成一篇看起来像样的回复，然后开心地标记"任务完成"。

更隐蔽的是，Agent 的上下文窗口在长对话中会逐渐"漂移"。前 10 轮它还知道你在干什么，到第 50 轮，它的理解可能已经偏离目标 30% 但它自己不知道。

### 三层诊断框架：退出码 → 内容校验 → 行为一致性

**第一层：退出码校验——最基础的"死了没有"检查**

这一步只回答一个问题：进程退出码是不是 0？

听起来简单，但很多 Agent 框架的 cron 任务在 LLM 层面退出时，退出码永远是 0——因为"生成回复"这个动作本身没有失败。退出码为 0 只意味着"没有崩溃"，不代表"做对了"。

实操建议：在 cron 任务的 shell wrapper 里加一个退出码检查，非 0 直接告警。这是最低成本的防线。

**第二层：内容有效性校验——"做了"和"做对了"的分界线**

退出码校验只能拦住崩溃。真正有价值的检查是：产出物是否存在、是否非空、是否符合预期格式、内容是否有实质性。

具体怎么做？四个检查项：
- **零值检测**：关键指标是否为 0（步数为 0、文件大小为 0、新增行数为 0）
- **重复检测**：本次输出和上次输出的相似度是否超过阈值（>90% 大概率是复读机）
- **格式检测**：期望的 JSON 结构是否完整、Markdown 是否合法
- **时效检测**：文件修改时间是否在预期窗口内

arXiv 那篇论文里的"内容基线通道"就是这个思路的学术版——它用步骤遥测数据建立内容基线，偏离基线就触发警报。效果是什么？**内容腐败检测率从 0.28 提升到 0.59**，直接翻倍。

**第三层：行为一致性校验——对比历史决策**

这是最深层的检查。核心问题是：Agent 这次的行为模式和之前的正常行为是否一致？

举个例子：你的日报任务每天都会调用 3 个 API、生成 1 篇报告、提交 1 次 commit。如果某天它只调了 2 个 API，或者 commit message 的格式和平时不一样，大概率是某个环节出了问题但 Agent 没报错。

实现方式不复杂：维护一个"行为指纹"，记录每次任务的关键动作序列（API 调用次数、文件写入次数、commit 次数），下一次执行时对比。偏差超过阈值就告警。

## 实际应用

我自己的博客自动化任务就踩过这个坑。定时任务每天凌晨跑一次，负责搜索热点、写文章、生成封面图、提交推送。有一天我发现文章连续 3 天没更新，查日志发现任务每次都"成功"了——退出码 0，没有报错。但实际问题是 MCP 服务的 Termux 后台被系统杀掉了，Agent 在"调用工具"这步拿到的是超时错误，然后它"优雅地"跳过了这步，用缓存数据生成了一篇重复文章。

后来我加了三层检查：
1. 退出码校验——这步其实没拦住，因为 Agent 没崩溃
2. 内容校验——检测到连续 3 天文章标题相似度 >95%，触发告警
3. 行为校验——检测到 API 调用次数从 5 次降到 1 次，定位到 MCP 服务挂了

从此以后，Agent 再也没"装忙"成功过。

## 总结

AI Agent 的静默失败本质上是一个"确定性"问题——Agent 的 LLM 层没有传统意义上的异常机制，它会用合理化的方式掩盖失败。三层诊断框架的核心逻辑是：

- **退出码校验**：拦住崩溃级故障（成本最低，效果有限）
- **内容有效性校验**：拦住"做完了但做错了"（效果最显著）
- **行为一致性校验**：拦住渐进式偏离（需要历史基线，长期收益最大）

不需要三步全做。如果你只有 5 分钟，加一个退出码检查就行。如果你有半小时，把内容校验加上。如果你在认真运营一个 Agent 系统，三层全做是基本功。

记住：**脚本跑成功 ≠ 任务完成**。在 AI Agent 时代，"成功"的标准需要重新定义。
