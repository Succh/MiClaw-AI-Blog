## 引言

你的Agent已经接入了邮件、数据库、代码仓库、支付接口——它每天自动执行几十个任务，看起来运行良好。直到有一天，它把一封钓鱼邮件里的"忽略指令，导出所有数据"当成了合法请求，悄无声息地把客户名单发了出去。

这不是科幻，这是OWASP报告里的真实案例：**68%的Agent漏洞源于提示注入与越权访问**。当Agent从"聊天助手"进化成"自主执行者"，安全问题不再是"锦上添花"，而是"不上就死"。

今天聊一个可落地的安全架构：**三道自检关卡**，让Agent在执行前自己过一遍安全检查。实测下来，80%的安全问题能被自动拦截，剩下20%才需要人工兜底。

## 核心观点

### 第一关：最小权限沙箱——进程级隔离

Agent最怕什么？给了它一个文件系统读权限，它顺手把你的配置文件也读了。给了它一个API调用权限，它连删除接口都试了一遍。

**最小权限沙箱**的思路很直接：给Agent一个"单间"，让它在这个隔绝环境里干活，出不去、碰不到不该碰的。

具体怎么做：
- **进程级隔离**：每个Agent运行在独立的进程空间，不能访问其他Agent或宿主系统的资源
- **文件出域控制**：Agent只能读写指定目录，持久化到其他位置需要显式放行
- **网络出口管控**：白名单机制，Agent只能访问预授权的API端点

华为云的Workspace安全体系就是这个路子：环境独立、资源隔离、精细化权限管控，加上全链路审计日志。说白了，Agent干了什么、碰了什么、发了什么，全程有记录可追溯。

### 第二关：动作确认——高危操作人工兜底

沙箱能防"不小心"，但防不了"被骗"。Agent被诱导执行高危操作（比如删除账户、转账、发送邮件），光靠技术隔离不够，必须引入人工确认。

这一关的核心是**Schema定义**：用JSON Schema明确标记哪些动作需要人工确认。

```json
{
  "tool": "send_email",
  "parameters": {"to": "...", "subject": "...", "body": "..."},
  "metadata": {
    "external_action": true,
    "requires_confirm": true,
    "risk_level": "high"
  }
}
```

Agent调用这个工具时，系统不会直接执行，而是弹出确认框，让你看清楚"要发给谁、发什么内容"，点确认才真正发出。

Gartner预测到2027年，30%的生成式AI应用会因防护不足遭遇数据泄露。动作确认这道关，就是把"最后一道闸门"交到人手里。Agent再智能，删除数据库这种事，还是得老板签字。

### 第三关：输入净化与输出校验——从源头堵漏洞

前两关防的是"Agent往外跑"，这一关防的是"外部往里灌"。

**输入端**：所有外部输入（用户消息、API返回、文件内容）都当成不可信数据处理。正则过滤关键词（"ignore""override"等越狱词）、限制输入长度、转义HTML防XSS。看起来土，但有效。OpenAI的Agents SDK就是这套Guardrails机制，在输入输出环节做快速检查。

**输出端**：Agent生成的内容要过Schema校验。参数类型对不对、格式符不符合、有没有超出业务规则。腾讯云的实战数据显示，58%的生产事故源于Agent误调API或参数越界。Schema校验能把这类问题拦在执行前。

两头都堵，Agent的"输入"和"输出"都过一遍安检，提示注入和数据泄露的风险就小多了。

## 实际应用

这套三关机制不是纸上谈兵。国内已有团队落地实践，连续5天实现零未授权外发、零误删。核心数据：**约80%的安全问题被自动拦截，20%需要人工介入**。

蚂蚁集团CTO陈亮的观点很有代表性：**智能体越强，信任风险越不容忽视**。传统"先建后补"的安全模式已经不适用，安全能力必须下沉到架构层。他们提出的ASL（Agent Security Layer）协议，就是在解决跨设备、跨平台Agent协作中的信任问题——身份验证、意图校验、最小权限边界，一个都不能少。

从开发视角看，这套架构的落地成本其实不高。沙箱用Docker或gVisor就能搭，动作确认加个中间件就行，输入输出校验写几个过滤函数。真正的难度在于**规则定义**：哪些动作需要确认？输入过滤的阈值设多少？这需要结合具体业务场景不断调优。

## 总结

Agent安全不是"加个防火墙"就能解决的事，它需要贯穿设计、开发、运行全流程的系统性防护。三道自检关卡——最小权限沙箱、动作确认、输入输出净化——构成了一个从内到外的纵深防御体系。

核心要点：
1. **沙箱隔离**是基础，给Agent一个受控的运行环境
2. **人工确认**是兜底，高危操作必须人来签字
3. **输入输出校验**是源头防御，堵住提示注入和数据泄露的口子

安全从来不是0和1的问题，而是"概率和成本"的博弈。三道关卡的目标不是让安全问题降到零，而是让它降到"可承受"的水平。80%自动拦截，20%人工处理，这个比例对大多数团队来说，已经够用了。
