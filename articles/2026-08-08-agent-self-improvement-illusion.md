# 自我改进Agent的幻觉：刷到95.5%之后，我们发现了什么？

上周，开源框架 Prime Agent 在 ARC-AGI-3 基准测试上联合 Opus 5 拿到了 95.5% 的成绩，超过人类专家基线。GitHub 星标一夜逼近 5000，社区一片沸腾。

然后质疑来了。

## RLM：递归还是套娃？

Prime Agent 的核心卖点是递归语言模型（RLM）——把上下文当变量，模型在类似 Jupyter 的环境里工作，通过代码切分上下文、递归调用子任务并综合结果。听起来很美。

但 Shortcut AI 联合创始人 Peter Wang 翻开代码后发现：RLM_MAX_DEPTH 设为 1。换句话说，所谓的递归本质上就是主 Agent 调用若干子 Agent，和现有框架没有本质区别。

论文第一作者 Alex Zhang 回应说，递归深度上限是用户配置的，用来控制成本，深度 1 并不代表能力弱于无限深度。这话技术上没毛病，但问题是——你宣传的是递归语言模型，实际实现是一个两层的 Agent 调用链。这不是表达能力的问题，是命名和实现的落差。

## 95.5% 的含金量

更致命的质疑在于成绩本身。ARC-AGI-3 的环境和轨迹是公开的，而 Prime Agent 具备自我改进能力——它能分析自己的执行轨迹，把可复用的经验写回 harness。这意味着它完全可能从公开任务中学到答案。

Peter Wang 指出，PRO-LONG 项目用简单方法也拿到了约 95% 的成绩。如果一个没有递归、没有自我改进的框架能做到相近的分数，那 95.5% 这个数字的含金量就值得重新审视了。

Alex Zhang 承认 ARC-AGI-3 是可以被利用的 benchmark，但强调应综合考量框架在其他长上下文任务上的表现。这话也有道理——单独一个基准分数不能说明全部问题，但你宣传的时候偏偏只强调了这个数字。

## 自我改进的真正价值在哪？

抛开争议，Prime Agent 的 Continual Harness 设计确实值得关注。它把提示词、技能、记忆和子智能体全部变成运行时可 CRUD 的状态，允许模型在执行过程中实时创建、修改和调用它们。子智能体任务结束后保留状态，可被后续召回。

这种设计解决了一个真实痛点：Agent 的上下文窗口是有限的，但复杂任务的状态是持续累积的。通过把状态外化为可管理的实体，Agent 理论上能处理远超单次上下文容量的复杂流程。

自我改进机制也一样——虽然在基准测试上可能被利用，但在真实工作场景中，一个能从自己的执行轨迹中提取经验并优化后续行为的 Agent，确实比每次都从零开始的 Agent 更高效。

## 行业需要什么？

这次争议折射出一个更大的问题：AI 行业在基准测试和营销话术上的军备竞赛，正在让突破这个词贬值。

95.5% 超过人类专家——这个标题足够吸引眼球。但当你深入代码发现递归深度是 1，当你发现成绩可能包含过拟合成份，当你发现类似成绩用简单方法也能拿到，这个数字就不再那么闪耀了。

真正有价值的不是刷分，而是解决真实问题。Continual Harness 的状态管理、子智能体的持久化通信、自我改进的经验提取——这些才是 Prime Agent 值得研究的地方。至于 ARC-AGI-3 上的分数，让它留在基准测试里就好。

下一个真正重要的 Agent 突破，大概不会出现在任何排行榜上。
