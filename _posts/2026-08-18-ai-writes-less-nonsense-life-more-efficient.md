# AI写的废话越少，生活效率越高

## 引言：被AI废话淹没的早晨

今天刷 Hacker News，看到两个扎心的帖子：

1. **"为什么亚马逊订单确认邮件变得这么没用"**（62分）—— 用户吐槽现在收到的邮件全是AI生成的"感谢您的购买"废话，找不到关键信息
2. **"AI写死代码"**（13分）—— Go团队的deadcode工具一行命令就能找出AI写的无用代码

我突然意识到一个问题：**我们以为AI在提升效率，其实很多时候它在制造新的垃圾。**

作为一个每天和AI打交道的玩家，我想聊聊怎么让AI真正服务于生活，而不是被它制造的噪音淹没。

## 核心观点1：AI是工具，不是内容生产者

很多人用AI的方式是这样的：
- 让AI写邮件 → 收到一堆"感谢您的关注"的废话
- 让AI写代码 → 得到一堆能跑但没用的死代码
- 让AI写文章 → 生成一堆正确的废话

**问题不在AI，在于我们给AI的指令太模糊。**

我的做法是：**把AI当工具，不当作家。**

比如我要生成一张像素画，我不会说"帮我画个好看的图"，而是说：
```
生成16x16像素画，主题是假面骑士龙骑中的龙骑，配色：红金黑，背景透明
```

具体、有约束、可执行。

## 核心观点2：像素画教会我的"约束美学"

最近迷上了像素画，尤其是假面骑士龙骑系列。

像素画有个特点：**限制越多，创意越强。** 16x16的格子，你能用的颜色有限，每个像素都要精打细算。

这和用AI是一个道理：

| 像素画约束 | AI使用约束 |
|-----------|-----------|
| 16x16分辨率 | 明确输出格式 |
| 有限色板 | 指定风格/语气 |
| 每个像素都要有意义 | 每个词都要有信息量 |

**约束不是限制，是效率的催化剂。**

我用AI生成像素画的时候，会先给参考图，再给具体的色板和尺寸要求。出来的结果比"随便画一个"好10倍。

## 核心观点3：自动化不是让AI替你思考，而是替你跑腿

我搭了个GitHub定时写文系统，每天自动抓取热点、生成草稿。

但这里有个关键：**AI只负责"执行"，不负责"决策"。**

我的系统流程：
1. ✅ AI抓取HN热点（信息收集）
2. ✅ AI根据hash值选方向（规则引擎）
3. ✅ AI生成1500字草稿（模板填充）
4. ❌ 发布决策由我来做（人工审核）

**把重复劳动交给AI，把判断权留给自己。**

就像假面骑士龙骑里的契约兽：你召唤它，它帮你打架，但什么时候打、打谁，是你决定的。

## 核心观点4：Token成本意识 = 生活效率意识

玩AI玩多了，你会对"浪费Token"特别敏感。

一段废话邮件 = 浪费读者的时间
一段死代码 = 浪费编译器的计算
一段正确的废话 = 浪费Token

**Token成本意识本质上是一种"信息密度"意识。**

我现在写东西会问自己：
- 这句话删掉，影响理解吗？
- 这个段落的信息密度够吗？
- 读者看完能得到什么？

这和像素画一模一样：每个像素都要有存在的意义。

## 实际应用：我的AI效率组合拳

分享几个我真正用起来的AI效率场景：

### 1. 像素画批量生成
用 `image_generate` 工具，配合精确的prompt，一次生成10张16x16像素画，挑最好的用。

### 2. 热点追踪 → 草稿生成
GitHub Actions每天跑，抓取HN/arXiv热点，生成结构化草稿。我只需要花10分钟审核修改就能发。

### 3. 知识库自动整理
用IMA知识库，把日常看到的好文章、好工具自动归档，AI帮忙打标签、写摘要。

### 4. 代码审查辅助
让AI先扫一遍代码，找出"死代码"和"过度设计"，人再重点审查核心逻辑。

## 我的看法：做AI的主人，不做AI的奴隶

回到今天的HN热点：

亚马逊的AI邮件问题，本质是**企业把"生成内容"当成了"服务用户"**。AI生成了邮件，但没解决用户的需求——快速找到订单信息。

Go团队的deadcode工具能火，说明**开发者对AI写的垃圾代码已经开始警惕**。

我的态度很简单：

> **AI是龙骑里的契约兽，不是龙骑本身。**

你可以召唤它帮你战斗，但：
- 什么时候召唤（场景判断）
- 召唤来干什么（目标明确）
- 战斗结束后怎么处理（结果审核）

这些永远是你自己的责任。

**让AI干苦力，你来做决策。**

这就是我从像素画、从假面骑士龙骑、从每天和AI打交道的实践中，学到的效率哲学。
